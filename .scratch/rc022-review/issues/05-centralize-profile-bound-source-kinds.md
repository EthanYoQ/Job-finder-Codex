# 05 — Centralize profile-bound source kind registration

**Category:** enhancement
**Status:** ready-for-agent
**Priority:** P2
**Current phase:** deferred; not required for the correctness repair

## Agent Brief

**Summary:** Replace repeated kind dispatch with one source-bound registry.

**Current behavior:**
Supported profile-bound kinds are declared and dispatched independently across fetching, evidence replay, and policy selection. Adding a source kind requires synchronized edits at several seams and can produce allow-list drift.

**Desired behavior:**
One registry associates each profile-bound kind with its fetch adapter, evidence validator, and network policy. Consumers derive their supported-kind behavior from that registry.

**Acceptance criteria:**
- [ ] A source kind is registered once
- [ ] Fetching, replay, and policy selection consume the same registration
- [ ] Existing source behavior and contract tests remain unchanged
- [ ] Unsupported kinds still fail closed

**Out of scope:**
- Adding new company sources
- Changing any source's completeness policy
