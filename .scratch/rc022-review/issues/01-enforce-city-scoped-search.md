# 01 — Enforce city-scoped job search

**Category:** bug
**Status:** ready-for-agent
**Priority:** P1

## Agent Brief

**Summary:** Remove the all-locations bypass so every job search is scoped to one selected city.

**Current behavior:**
The search request accepts the `全部地点` sentinel. That value suppresses the database city predicate and allows jobs whose only location is outside China to enter grouped search results.

**Desired behavior:**
Every accepted search request names a concrete city. The interface must not offer an all-locations choice, and the server must reject the legacy sentinel before reading jobs. Nationwide and China-wide jobs remain eligible within a concrete-city search.

**Key interfaces:**
- Search request validation — reject the legacy all-locations sentinel as a non-city value
- Database-backed job search — always build a city predicate for accepted requests
- Job discovery interface — expose only concrete city choices
- Demo filtering — mirror production city-required behavior

**Acceptance criteria:**
- [ ] The legacy all-locations value is rejected before any job query runs
- [ ] Every accepted search uses the selected city plus the existing nationwide/China fallbacks
- [ ] The discovery interface has no all-locations option
- [ ] Existing concrete-city searches remain unchanged
- [ ] A public-seam regression test proves an India/APAC-only job cannot be returned through the legacy sentinel

**Out of scope:**
- Adding arbitrary free-form city entry
- Changing company coverage browsing
- Changing nationwide/China location semantics
