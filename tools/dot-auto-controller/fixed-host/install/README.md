# Fixed installation caller (source candidate)

The default renderer emits `INSTALL=null` and returns DISABLED before any tool
call. A bound renderer requires measured new commit/tree/holder hashes, the
original read-only candidate query, the exact retirement read, and the actual
expected reader identity. This directory does not contain a production binding.

The fixed no-argument functions entry captures the official GitHub commit and
Git-object readers, official Supabase query tool, and the existing dot execution
session tools. The original Promises and serialized responses remain in the
same closure. No saved acceptance report is accepted as a qualification input.
The Git-object URL is built from the pinned repository and commit, never a URL
returned by a response.

The proposed holder protocol is INSTALL_READY (with private nonce), then stage,
reader, publish, finish. Stage performs expensive source/dependency/native checks
before the four final official reads. The reader command invokes the original
readerIdentity gate. The same EX owner stays alive throughout every await.
Publish receives original response bytes/hashes/times plus that same reader
observation, and must recheck their original deadlines immediately before its
first publication. Finish requires completed publication and all final checks.
Abnormal completion preserves durable UNKNOWN and never retries publication.

`facts.mjs` is only a pure decoder, not an authority mechanism. The synthetic
Node protocol tests use fake connector and holder tools and establish no LIVE
qualification. Filesystem/PTY/real original installer integration tests must be
reported separately. The old validated root 4732916 and its unconditional-HOLD
installer remain unchanged.
