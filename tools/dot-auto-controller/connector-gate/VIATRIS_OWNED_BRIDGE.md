That loader can create and remove a temporary config under borrowed `node_modules/.vite-temp` even with an external cacheDir, so those runs cannot be described as wholly read-only. The current directory was empty when inspected. All 15,645 dependency regular-file hashes/byte counts and 25 symlink targets matched the frozen manifest, with no missing or extra files. No immediately-before-first-run complete directory metadata snapshot exists; earlier parent tests also changed this directory, so its full metadata history is not attributed to this run. No directory, timestamp or permission was reset.

Subsequent small runs use the independently checked Vitest API with `config:false`, `configFile:false`, external cacheDir/TMPDIR, the same single-fork/node/90-second conditions and no setupFiles, matching the original configuration. An explicit new fork self-test then disproved the assumption that a parent Node --require automatically propagates: Vitest filters it out. That failed self-test attempted only localhost:1 and received ECONNREFUSED; its failure log is retained. Both the API runner and source config now set poolOptions.forks.execArgv to the absolute original no-network preload. The test checks execArgv and require.cache before invoking any transport, then checks net/http/https/tls/fetch all throw OFFLINE_NETWORK_FORBIDDEN. With this correction the 54 focused tests pass. The guarded probe and final focused run compared all 17,092 dependency entries including mode/size/mtime/ctime/inode before and after and found them identical. Atime is excluded because read access can change it. This correction does not turn small tests into runtime qualification.
