## Exact implementation

The only mutation of the original compiler is a private UUID allocator seam. The existing exported compiler calls the same implementation with `randomUUID`. The new `prepareDbStartedCloudPublicationReplay` records identifiers privately on its first compile. Every `recompile()` reruns the complete original context loader, `buildAtomicRuntimeCommit`, full `prepareAtomicWritePlan`, original lifecycle, delta receipt/compiler, and DB-started controls. It reuses the private identifiers solely to compare every SQL byte, terminal/commit value, holder, and expiry. Missing or extra allocations fail. UUID order and the original DO-delimiter collision loop are preserved. No allocator or tape is supplied by callers. No global crypto, Date, loader, extracted/evaluated source, generic SQL parser, or saved SQL assertion is used in production code.

The Takeda gate accepts only the current source ID/configuration and owner, project `yiopvxysxrtrnvqxwgbx`, original portable policy, existing 49-migration delta profile, and exact 16-field candidate projection. Original compiler checks remain the source of candidate derivation, planned-batch identity, schema/function/trigger checks, context CAS, expiry, ownership, locks, and all transaction postconditions. No SQL50/private ledger is introduced.

`prepareTakedaConnectorPublicationReview` retains the actual owned source/admission. It snapshots inputs before awaiting. It checks the executing Node profile and reads the actual local source/runtime byte trees using the original algorithm. It rejects mixing another producer root, build, source, or current context. This is an after-import local integrity check. The existing trusted pre-import host binding remains mandatory for any future integration; the gate does not claim to replace it or prove database registration.

The gate verifies physical original and restored archive roots independently. Each is rebuilt with original `makeArchiveBundle`/`verifyArchivedSourceEvidence`; the complete sidecar, full tuple, every artifact identity/metadata, byte count, SHA, and body must equal the sealed bundle. It then calls original `issueSourceQualityAdmission` with the original owned result, causing complete strict evidence, pagination, adapter, normalization and archive replay. The return must be the same owned admission object. This does not use the Astellas-specific verifier that is a no-op for Takeda. Saved receipts and retained-capture origin do not qualify.

Preparation, review, and capability consumption all recheck time/input scope. Review and consumption repeat runtime/archive checks and full compilation. The request has strict keys, the original request-body SHA, exact SQL, original expiry, and exact dispatch reserve. A private WeakMap issues an empty frozen capability. A copy or another process cannot consume it. A failed review cannot be retried on the same review instance; consumption deletes its capability before any await, including on later failure. Checksums remain evidence binding, never permission.

The original context must meet the existing 60-second response-age bound when received. Later review preserves that exact immutable snapshot and relies on the original SQL context CAS (only diagnostic checkedAt is excluded there). It does not add a new 60-second total review budget. Timestamps cannot be renewed in saved input. For a subsequent accepted delta result, the exact original successful `CrawlObservation` must match its receipt and tuple; the pending capture must be at least 12 hours after that observation. The first accepted run has no prior observation. This is a local precondition on the host-supplied context; authentic official read provenance still belongs to the future trusted bridge. It does not create a schedule or alter source cadence.
