# Product Design PRD 审核记录

审核日期：2026-07-07

审核对象：

- `docs/prd/pharma-job-aggregator-prd.md`
- `docs/research/p0-company-and-reuse-research.md`

## 结论

Product Design 审核未推翻核心产品方向：P0 首页应是城市必选的职位发现工作台，搜索结果默认按公司聚合，移动端优先，前台边界保持“职位发现与跳转”。

需要补强的部分：

1. 城市必选首页依赖真实覆盖密度，PRD 需要承认 50 家可抓取是上线前置目标。
2. SEO、反爬、无公开 API 存在张力，需要明确哪些页面可索引、哪些路径不可索引。
3. 隐私同意弹窗可能打断首次任务，弹窗必须极简，政策页面可在未同意前访问。
4. 17 个职位类别、多选、关键词、公司筛选、排序和新增筛选叠加后，移动端需要明确层级。
5. 公司覆盖页、反馈、推荐公司、新岗位筛选等辅助流程不能抢主搜索流程。

## 已采纳进 PRD 的修改

- 首页定义为城市必选的职位发现工作台。
- 未选城市时不展示空结果列表。
- 移动端优先级固定为：城市选择 > 结果摘要 > 公司聚合列表 > 可选筛选。
- 职位类别、关键词、公司筛选、排序默认收起到筛选入口。
- 已选条件用紧凑 chips 展示。
- 公司卡片收起态只展示公司名、匹配岗位数、新岗位提示和展开入口。
- 公司展开态展示极简岗位行。
- 长列表公司默认只展示前 N 条岗位，再提供查看更多。
- 公司覆盖页、反馈、隐私政策、服务条款均为辅助流程。
- SEO 只开放有限页面；深分页、组合筛选、内部 API、后台、批量路径不可索引。
- 前台 CTA 使用“查看官方职位”或“去官方招聘页”，不使用“立即投递”。

## 未直接采纳的建议

第一轮 Product Design 建议可后推公司覆盖页搜索、岗位数排序、新岗位筛选、公司推荐、城市/类别 SEO 页。当时未直接砍掉这些功能，因为它们已经经过用户确认。第二轮审核后，出于强制隐私同意和反爬边界，城市/类别结果页 SEO 已改为 P0 不开放。

## 第二轮独立审核补充

审核来源：独立 Product Design subagent `019f3a0d-0b34-7ce3-83d0-e9b58c5503cb`

审核结论：核心方向成立。P0 继续定位为“城市必选、按公司聚合、官方职位发现与跳转”的移动端优先网页应用，不应退化成公司目录页。最大产品风险是强制隐私同意、有限 SEO、强反爬之间的边界。

第二轮必须修订项已采纳：

- 将“已验证可抓取”的完整定义合并进 PRD 正文，避免把“能打开招聘页”误认为可抓取。
- 明确当前状态不是 P0 可正式上线状态；正式发布前必须满足 80-120 家候选池和至少 50 家已验证可抓取公司。
- 采用更保守的 SEO/隐私边界：P0 不开放城市/类别结果页索引；未同意前只允许访问隐私政策、服务条款和不加载职位结果的静态首页外壳。
- 为“查看更多本公司岗位”加入受控加载规则，禁止无限深分页、批量枚举、导出路径或稳定公共 API 合同。

第二轮建议修订项已采纳：

- 职位类别筛选采用收起式筛选面板和可搜索多选，不在移动端首屏铺满 17 个类别。
- 无结果页只提供少量放宽动作：清空岗位方向、清空关键词、查看该城市全部公司。
- 反馈入口优先放在公司卡片或岗位行附近，并自动带上下文。
- 增加移动端可访问性验收项：触控面积、焦点管理、键盘关闭、展开状态读屏可识别。
- 隐私政策需包含数据保留期限、删除/导出通道、后台访问权限、数据类别和用途；韩国服务器跨境合规仍标注为未证实。
