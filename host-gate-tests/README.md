# Gilead offline packet and owner gates

Run from this workspace:

```sh
bash /workspace/scratch/5e9614251709/jb-incremental-proxy-runtime-20261007T0057Z/verification/gilead-producer-runtime-0551Z/host-gate-tests/run-offline.sh
```

Everything generated by this harness stays under `host-gate-tests`. It reads the new `hosts/gilead` implementation and frozen producer commit `d6190919d17c8ba4ee721daa2087d3c09bded7fa`. It does not register a candidate, execute SQL, call a live endpoint, start the producer/supervisor, or activate the actual host. The actual installed host is already bound. Tests read only explicit safe templates, create isolated unbound fixtures, and never read its activation, control or context files. The restoration helper uses an import bridge to the existing physical producer; the binder verifies that real clean Git/runtime identity.

The fake candidate version 52 and repeated `d`/`e` database hashes are explicitly synthetic. They are not the owner's actual version or fresh DB identity. A passing report is not a live acquisition, production qualification, registration receipt, or launch authorization.

## Entrypoints

- `generate-synthetic-packet.mts`: Uses the new producer compiler and ten invented Gilead jobs. Every fetch is answered by an exact-URL local stub. Output is a synthetic archive, packet JSON, SQL text, and manifest. Default output is a new timestamped directory; an explicit output must also stay under this test root. SQL is compiled and inspected, never executed. Set `JOBFINDER_CLOUD_SOURCE_ID=source-gilead-china-social` before loading producer modules
- `verify-host-offline.mts`: Regenerates a fresh packet, preserves all original 22 Grifols packet/reviewer/error-envelope gates, and adds Gilead owner tuple and persisted LF assertions. The Python reviewer reads a separate synthetic host fixture. Every rejection starts without a publication-review file, preventing a false-positive rejection caused only by the review file already existing
- `verify-owner-gates.mts`: Calls the exact retained pre-activation loader/starter templates and checks rejection before tools or session writes. Positive loader fixtures replace only the exact owner-candidate/DB constants in an in-memory string. Exercises the real binder with synthetic owner/readback files, verifies every emitted hash and exact compiler context bytes, checks negative owner/readback fields, and requires `PREPARED_NOT_ACTIVATED`

## Byte-level persistence checks

- The actual Python reviewer writes diagnostics JSONL with real `0a` record boundaries and a directly parseable review JSON ending in `0a`
- The actual combined-command builder is extracted without executing the starter. Its output is persisted by the actual host helper's `save` through the real local `apply_patch` command. The resulting command has six real LF bytes. It is never executed
- Actual preflight `check` mode runs the verified Node/runtime/clean-build checks and a local synthetic archive smoke. The resulting JSON report must parse without normalization and end in byte `0a`. Launch mode and producer execution are never invoked
