# Job Finder 配对网页发布恢复

目标是在当前授权范围内建立可恢复、可核验的主网页与兼容后备。沿用用户指定的 dot 云采集 → 官方 Supabase → 同一阿里云实例网页架构；本技能不授权改架构、换环境、迁移数据库、启用 producer、接受站点条款、改变告警状态或防护配置。告警只读关联使用既有渠道权限。

先分清这次允许完成哪一层：离线包、网页进程、HTTP 数据验收、浏览器行为、持久化、数据库增量。分别报告结论；一层通过不能代替另一层。已有可靠证据可复用，但执行前重新核对会变化的状态。

若实际阻断发生在官方来源解析或证据编译，先按[项目来源与证据问题记录](../../docs/job-finder/source-evidence-repair-notes.md)定位对应合同，不以网页重新部署替代来源修复。该文档是项目参考，不扩大本技能的部署职责或执行权限。

## 冻结与认领

- 固定角色、基线、目标、端口、入口路由及恢复目标。先只读观察真实 Python/Node 版本、完整启动参数（含 env-file）、服务账户目录权限、PM2 状态和 nginx 二进制绝对路径，不能靠通用 root/mode 假设修权限。
- 固定包和每个分片的完整字节、长度、SHA256；新命令的 Name、内容 SHA256、目标和预期效果必须在提交前持久化。提交意图、Popen 开始/退出、官方 InvokeId 各自及时 fsync。优先明文可审计脚本配合哈希，不增加无必要的 Base64 + Zlib + exec 包装。
- 一个命令由一个明确执行方提交。已有提交意图但未取得确切结果时，进入 UNKNOWN，只读核对并认领原调用；不因客户端超时、列表缺席或经过足够长时间重投。终态还需检查退出码和实际后置条件。
- UNKNOWN 未查清时，新内容目录部署必须有用户明确覆盖该风险与冲突边界的授权；可复用本轮已充分覆盖的授权，不能由代理自作风险决定补足。目录路径隔离不能阻止旧 root 权限代码影响整个实例。保留原 UNKNOWN 结论，不借新部署成功将它改写为完成。

提交不明、MCP 取消/拒绝、告警归因或备份时读[命令证据与恢复契约](references/command-evidence-and-recovery.md)。

原 exec 监控缺失、预算恢复、异步作用域漂移或应用层功能隔离时，读[原执行监控与功能隔离](references/monitor-evidence-and-functional-isolation.md)。沿真实 helper 调用链核对最终 SQL 门，不能把 owner 调用 helper 前的检查当成工具执行边界；终态回包先保存原证据，再核对完整身份后接受。该参考区分 OS UNKNOWN 与已证明不能继续 HTTP/PUBLISH 的特定应用路径，不放宽未决 root 命令、原调用重投或部署授权门。

## 重建运行身份

- 安全 Git 镜像身份不等于原生产运行身份。用清单验证每个必需基线文件的路径、字节、哈希和适用 mode，再恢复到新的不存在目录；缺少必需基线就停在缺口，不把猜测当完整恢复。
- 独立复制并验证真实依赖，不能用跨目录 node_modules symlink 绕过应用的身份算法。保留兼容的已生成 Prisma client/native engine；不得因网页部署顺手安装依赖、生成 client 或执行迁移。
- 新源树、真实依赖、构建产物和兼容静态资源全部就位后，按应用现行算法生成新运行身份并回读；禁止复制旧 build-identity 充当新身份。

恢复读合同、环境绑定和运行身份细节见[运行与验收要点](references/runtime-and-acceptance.md)。

已授权恢复涉及 dot 云网络/runtime 诊断、启动文件 pin 或同批公开验收时，另读[代理运行时与同批验收](references/proxy-runtime-and-same-batch-readback.md)。该参考不授予采集、数据库写入或部署权限，不改变本技能的发布恢复职责。

证书有效但网页误拒、增量恢复改变全站派生汇总、验收失败缺少详情，或已确认失败后另起恢复尝试时，读[时间语义与失败验收修复](references/time-semantics-and-failed-acceptance.md)。先区分不同事件的时间，再按来源和批次绑定；预期变化必须从独立输入推导，不可从待验输出反推放行。

## 受约束滚动与验收

- 内存、堆上限跟随角色和实际测量，不跟随端口，也不把历史阈值推广成所有服务器硬门槛。在本次授权的顺序内，先停非路由后备腾内存，验证新主后才切流；旧 nginx worker 按 PID + startticks 排空后，才停旧主并启动新后备。
- 两个新角色均需保留仍可能被旧页面引用的旧/新 hash assets，再生成运行身份，避免切换后懒加载 chunk 404。相同文件名不同字节要停下核对，不能覆盖碰撞。
- 同时验证真实进程、工作目录、完整参数、重启状态、监听 socket 归属与 HTTP 内容。健康端点或岗位总数相同不足以通过。
- 比较完整分页后的公开业务投影、来源状态、原始时间、显示/状态身份，以及实际下载静态资源的字节与哈希。主网页 check 关联协议和兼容后备无 check 协议分别验；只允许协议明确的有限获取/等待，返回后仍检查时间门。
- pending、error、partial、无法取得关联 check、混合快照和过期验收都不能记 PASS。CLI 失败或超时后先核实际进程/端口，再决定已授权恢复；不能把失败退出码当成“未执行”。

## 持久化与交付

仅在角色、路由与所需 HTTP 验收均符合目标后保存 PM2 清单，并回读名称、状态、cwd、端口、解释器、完整 args、host、策略和堆参数。再次核对活动进程与路由。保存及回读证明清单持久化，不证明主机重启演练。

交付只写已证实结果、证据位置与剩余缺口。网页 HTTP 验收不能证明浏览器五秒行为；网页发布不能证明 schema/producer 已启用；单条告警归因不能证明整机安全。备份按[最小恢复契约](references/command-evidence-and-recovery.md#最小恢复契约)区分安全源码和授权私有证据，不把机密或实际运行材料写入本技能。
