# 运行与验收要点

## 恢复合同与真实环境

读取现有进程的实际合同：解释器绝对路径及版本、args 的顺序与每个参数、cwd、host、角色对应端口和 heap、env-file 路径、必要的非秘密策略。保护原来已批准的秘密加载方式；核对文件/目录元数据，不打印或转存秘密值。真实服务账户目录可能合法地有不同 owner/group/mode，不能为满足错误的通用假设修改它。

先观察服务器解释器，再确定辅助脚本语法和标准库接口。仅做语法兼容检查不等于在对应 Python 版本执行过；离线验收必须说明这一差别。

源文件权限变严但内容未变时，先核对字节、长度、SHA256、owner 和路径关系。曾验证过的特例是原清单 0644、实际 0600 且字节完全相同：可以为精确匹配的输入收窄适配读取合同；不能 chmod 旧源，也不能放宽所有文件或接受内容差异。输出仍执行目标清单合同。

归档先验 SHA256/长度，拒绝越界路径、重复条目、非预期链接/特殊文件和超出合理体积的内容；固定允许的条目集合。恢复时所有输入先验证、后写新的不存在目录，不在旧运行根目录原地修补。

## 依赖和身份

- 独立依赖目录应验证来源、锁文件和完整树摘要。目录 symlink 被既有身份算法拒绝时，不能把链接身份当实际运行树；复制后还需核对允许的文件链接目标未逃逸新树。
- 核实生成的 Prisma client 可以导入、所需模型存在、native engine 适合实际机器。源码 schema 看似相同或本地生成成功不足以证明服务器生成物合格。
- 安全过滤后的 Git commit、包清单 runtime_tree_sha256 和应用 canonicalRuntimeTreeSha256 是不同合同，不能混用。使用新实际依赖/源树/静态资源生成应用身份，再回读验证。
- 将兼容旧页面所需 hash assets 加入新主、新后备；先校验文件名、内容哈希和碰撞，再生成身份。只有健康首页不代表延迟加载资源完整。

## 内存和切流

历史实例曾以启动前可用内存 600 MiB、启动后余量 192 MiB 验证，主/后备 heap 分别为 256/192 MiB。这些是该次项目实测及批准的配置，不是通用容量结论；新环境应根据真实基线、可恢复性和实际启动测量制定门槛，不能直接套值或加大 heap。

用角色映射区分旧主、旧后备、新主、新后备。端口复用不改变源基线或 heap 归属。每次变更前核对名称唯一、cwd、完整 args、进程 PID + startticks、监听 socket 归属、实际路由和剩余内存。

在已授权的滚动顺序中：停止非路由后备并确认进程/端口释放；启动新主并验收；以绑定的原配置哈希作前置条件修改/校验/重载 nginx；验证域名实际返回新产物；确认旧 worker 排空后才停止旧主、腾内存并启动新后备。排空依赖原 PID + startticks，不能只看端口已切换或进程名。nginx reload 会启动新 worker，并让旧 worker 完成已有连接，参见 [nginx 官方控制文档](https://nginx.org/en/docs/control.html)。

任一步失败先读取当前事实。PM2 条目为 errored 不证明没有遗留进程；查遍该角色的真实进程与端口后，若确证没有占用且恢复动作已授权，才恢复旧角色。CLI 超时可能发生在动作完成后，重投 start/stop/reload 不能替代核对。发现外部并发修改、身份变化或恢复条件不明时停在具体缺口。

## HTTP 证明什么

验收入口应明确绑定目标进程及其实际 socket；保留域名入口核验，不能用另一个恰好返回 200 的端口替代。对无筛选的完整 coverage/search 分页验证唯一公司/岗位 ID、每页归属、真实终止、总数与汇总一致，再比较集合。

保留未知业务字段、数组顺序、来源 ID/结果 ID、职位正文与原始时间等公开投影。只按协议明确排除动态包装字段，例如顶层 generatedAt；snapshotRefresh 单独比较，分页包装只能在完整分页验证后移除。不得为了让结果相等而归一化原始发布时间、观察时间、成功时间或关闭状态。

快照协议按实际角色处理：

- 主网页：关联 check 一旦取得，同轮 settling、coverage 和 search 页均保持它。初始 CURRENT 无 check 时，协议允许的一次额外普通 GET 必须使用原时间/请求预算；仍无 check 就 BLOCKED。UPDATING 无 check 直接阻断，不开启无限获取循环。已核实为新主的基线也采用此流程。
- 兼容后备：不得发送或要求 check。由已核实的角色/commit 合同与实际响应共同确定基线协议；首个响应缺少 check 不足以证明它是旧协议，也不能以“基线”标签假定它永远是旧角色。合同或协议仍无法确认时阻断，不猜测。
- 各页均须 CURRENT，并保持该端协议实际暴露的身份与 verifiedAt 绑定。新主/兼容新后备应验证 version、displayDataVersion、statusVersion、verificationVersion，并按现行算法重算 verificationVersion；旧基线缺少的新身份字段标为不可比较，不补造它们。跨进程 version/verifiedAt 可以不同，但可比较的 displayDataVersion/statusVersion 与业务/原时间投影必须一致。

每次响应结束后检查实际总耗时，每次 settling 响应及最终返回 CURRENT 前复查原 monotonic deadline。socket timeout 不是慢速分段响应的总时限；外围保留独立整体验收进程硬时限。不得因重试重置预算或混合两轮快照。

下载并对照目标 index 与所需 JS/CSS（含懒加载包）的字节和 SHA256；字体/标识等若只由离线包证明，应明确证据边界。HTTP 公开投影不暴露全部内部 sources，也不证明私有数据库逐行相同；有 statusVersion 也应区分“身份承诺匹配”与“已读取内部记录”。

结果至少区分 PASS、MISMATCH、BLOCKED/ERROR 和未完成。保存适量的计数、差异路径、哈希和耗时即可，避免把正文、秘密、check token 或原始响应写入通用报告。浏览器时限另行测量；站点条款或权限未获批准时，不用后台 GET 的成功替代浏览器完成结论。
