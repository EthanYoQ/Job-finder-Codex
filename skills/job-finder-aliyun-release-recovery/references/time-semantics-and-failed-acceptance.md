# 时间语义与失败验收修复

用于已有发布授权下的 reader 与验收故障。不授权新采集、库写入、换架构或扩大部署范围。本文保留可复用的问题、修复和反例；生产原件与回执仅保存在已经批准的私有证据目的地。

## 不同事件时间不能一概强等

一次 TRUE_A 增量恢复中，两个 reader 都把 delta 的原始 CrawlObservation.crawledAt 与 A 证书独立官方总量观测 observedAt 强等。有效原件因两次事件发生时间不同而触发 PORTABLE_DELTA_OBSERVATION_DRIFT，网页进入 HOLD。问题在读契约，不是“岗位未入库”。旧基线与新 reader 必须使用同一组原件对照，先确认库中批次及质量证据，再判断能否修读契约。

修复只拆开两种已有语义：

- 先通过原 A 证书质量验证；证书 observedAt 继续负责来源新鲜度与 lastSuccessAt，不替换或重签证书
- A delta 的岗位观测采用唯一已存 CrawlObservation.crawledAt。严格核对 source、sourceResult、batch、releaseCandidate、配置摘要、adapterVersion 和 canonicalOutputSha256；核对全部成功标记
- observedFrom/observedTo 必须分别等于该结果 startedAt/finishedAt，所有日期有效，crawledAt 位于该闭区间。接受时间不同不等于允许任意时间差；必须依靠身份、区间和原证据约束
- delta verifiedAt 仍绑定结果 finishedAt；CURRENT 的 lastConfirmedObservedAt 绑定本次原始观测。GRACE 绑定最后出现批次的原始观测与完成时间，并核对历史成员证明，不套本次时间
- 保持非 delta A、非 A delta 和既有 CURRENT/GRACE 可见性政策。不能为修一个来源给所有旧证书新增观测要求，也不能借机扩大可见岗位集合

对照包括：旧 reader 在同原件上拒绝、新双 reader 接受、原件字节未变、完整岗位 ID/投影/时间匹配。反例覆盖缺失/重复观测、逐项身份漂移、失败标记、区间边界外或无效时间、重算摘要后伪换证书时间，以及篡改历史 GRACE 引用。两端分别验收，源码相同不能替代角色验收。

## 派生汇总必须有显式预期

原首次发布验收错误地要求全站 lastUpdatedAt 不变。恢复一个合法新来源后，该派生字段可能合理变新。修复不是删掉字段或接受任意更大时间，而是先读实际聚合合同，再从冻结基线和独立合法新增证书计算预期。

首次失败的详细 helper stdout 没有留存，因此不能追溯证明该不匹配是那次失败的唯一原因；这里记录的是另行确定并可复现的验收缺陷。原失败和安全回退有独立回执，不能用后续复现实验补造缺失详情。

本案例合同是 max(旧全站 lastUpdatedAt, 新增来源合法证书 observedAt)。按真实 UTC 时刻比较，不能直接按不同精度字符串字典序比较。旧值更新时保留旧值，新值更新时采用证书原值，相等遵循现行实现的表示规则。无效日期和缺失值不能默默变成“现在”。若聚合合同或新增/移除范围不同，重新推导，不能把这个公式套用于所有汇总。

将预期同时纳入 search 和来源状态投影。其他公司完整投影、原始时间、顺序和非目标字段保持全等；目标公司岗位集合、生命周期时间、计数、城市/省份分面和发布汇总按独立冻结证据精确更新。未知字段仍比较。反例需证明：无关公司变化、汇总任意前进、被删字段、错误分面、目标集合或时间漂移都会失败。

## 先保存失败证据，再抛错或恢复

原控制器在 helper 非零退出后先抛错，丢失该次可用的结构化验收详情。修复应覆盖成功与失败，不把“写了 PASS 文件”当完整诊断。

1. 收集 helper 退出码、超时/执行异常、解析状态以及 stdout/stderr 长度与摘要；只接纳固定 helper 合同的允许字段，未知 JSON、原始 stderr、token、秘密和正文不得混入通用报告
2. 在抛出验收异常、执行已授权回退或宣布 PASS 前，保存结构化结果。采用私有临时文件、flush/fsync、完整结果的独占发布和目录 fsync。已有文件或 symlink 不覆盖；写入失败单独报告，不能宣称诊断已保存
3. 失败和 PASS 都保留原结果身份；错误响应、非零码、超时、超大或不可解析输出不得因证据落盘就变 PASS。新结果不覆盖原失败

至少以实际临时目录测试：非零+合法差异报告、非法 JSON、超时、未知字段/潜在秘密、已有文件与 symlink、保存失败、成功路径，以及抛错前报告已经可读。离线测试不证明断电恢复；需要对应环境的持久化验证才能作更强结论。

## 确认失败、回退与新尝试的边界

已核实本次运行失败并安全回退，与较早调用的 UNKNOWN 是不同记录。先用确切官方调用结果和当前进程、socket、路由核对本次回退，再在既有授权覆盖内使用新的尝试目录和身份继续。保留旧失败目录、命令意图、结果和恢复记录；新的 a02 尝试是另一次运行，不能把旧记录改写成成功。

新目录仅防止证据误覆盖，不能消除旧 root 调用风险。若仍有会影响主机的 UNKNOWN，继续遵守[原调用与 UNKNOWN 门](command-evidence-and-recovery.md#固定提交与-unknown)。模糊 MCP 取消归因已在同参考的 GitHub/MCP 章节处理，本文不改写或重复推定其原因。

## 已验证范围与交付

2026-10-07 的原件回放显示：修复后两端从同一已入库批次恢复 181 个公开岗位，原输入不变，来源证书时间和岗位观测时间各自保留。独立回放每端通过 159 项回归与 24 项原件检查；这属于离线层证据，不是线上验收。后续已确认失败的首次发布保留原回退证据，新的尝试完成主备 HTTP 验收和各 171 个静态资源核对。生产调用 ID、端口、路径与回执不收录于技能备份。

一次约四秒的浏览器样本只证明该次观察，不能写成“稳定五秒内”；HTTP PASS、进程清单保存、重启演练、持续性能分别给结论。新成功不改变历史 UNKNOWN。

运行 `python3 scripts/test-acceptance-invariants.py` 可验证本参考中的简化合成不变量。它不导入生产 reader、不连网、不读取真实业务数据，不替代实际 reader、控制器与部署测试。修改后按[最小恢复契约](command-evidence-and-recovery.md#最小恢复契约)冻结技能与测试白名单，保存每个文件完整路径、长度、SHA256、总数/总字节和备份目的地，再交唯一 writer。生产回执不进 GitHub；远端回读前不称备份完成。
