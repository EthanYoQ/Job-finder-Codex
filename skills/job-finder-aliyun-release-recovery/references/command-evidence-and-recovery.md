# 命令证据与恢复契约

## 固定提交与 UNKNOWN

每个命令先保存完整审阅过的 payload 字节、Name、SHA256、长度、目标、超时与预期后置条件。分片还需固定序号、单片哈希和完整归档哈希；新脚本内容使用新名称/摘要，不能覆盖旧意图。写入采用独占创建、flush/fsync 和父目录 fsync，防止进程中断后只剩不完整记录。

提交前固定 intent；Popen 后立即保存开始记录；返回或超时后及时保存退出记录；响应中已经收到 InvokeId/RequestId 时立即持久化，不因客户端退出非零丢弃它。避免自动重试写调用，且不能把停止本地 CLI 当成取消远端执行。缺少确认意味着 UNKNOWN，而非可安全重投。

按 exact InvokeId 查询官方结果；原汇总没保存时，可从已 fsync 的退出记录恢复同一 ID。没有 ID 时，以现有 Name、确切内容、目标与官方审计作只读关联，不能用新 RunCommand“试一下”。官方 [DescribeInvocationResult](https://www.alibabacloud.com/help/en/simple-application-server/developer-reference/api-swas-open-2020-06-01-describeinvocationresult) 用于读取执行结果；文档所述历史可查窗口有限，列表缺席不能证明从未执行或已经退出。

接受一个阶段完成需要调用身份、官方终态/退出码及目标后置条件一致。已到终态但业务结果不符仍是失败或待核对。有限等待耗尽只结束本轮等待，不会把 UNKNOWN 变成失败，也不自动授权新的部署。

旧 root 权限命令未查清时，新的内容寻址目录仅能降低误覆盖风险，不能提供整个主机的绝对隔离。需用户明确覆盖该风险和冲突边界的授权，再考虑独立部署；可以复用本轮已有充分授权，不能由代理自己的风险判断补足，也不得宣称原调用因此消失。

## 运维告警的精确关联

告警到来先保存并核对具体事实，避免继续新增变更掩盖状态。只用已授权的只读渠道取得告警原命令、原提交字节、官方回执和审计事件；若某项不可访问就保留归因缺口。

1. 对原始及告警展示的 payload 分别算长度和 SHA256；告警提供 MD5 时仅作额外交叉关联，不替代 SHA256。记录确有必要的展示归一化规则，不能为了匹配任意改写命令。
2. 若存在 Base64/Zlib 包装，在隔离本地按有限大小解码/解压，比较编码块及解码源码的字节和 SHA256；只读分析，绝不 exec、导入或运行待查 payload。
3. 关联官方 RequestId、InvokeId、命令名、目标和审计来源信息。时间接近或来源 IP 看似熟悉不足以闭合证据链；不能用地址外观推断归属。
4. 对照完整源码的实际副作用与用户授权。compile(source, filename, ...) 的 filename 可能只是诊断标签；必须另查实际创建行为和文件证据，不能当作落地文件存在的证明。
5. 给出针对该条告警的结论及依据。编码包装或持久化动作可能与检测有关，但未获厂商说明不能声称已知检测因果；单条已授权运维误报不代表整机或账户安全。

相关审计字段与查询方式以 [ActionTrail 官方事件查询文档](https://help.aliyun.com/zh/actiontrail/user-guide/query-events-in-the-actiontrail-console) 为准。归因完成不自动授权标记告警、加白或关闭防护，这些动作保持独立权限边界。

新恢复工作优先明文固定脚本加哈希，必要封装需保留可审计原文及双层摘要。减少不必要的 Base64 + Zlib + exec 是为了审计可读性与可复核性，不是为了绕过安全检测。

## 最小恢复契约

先区分技能备份、源码备份和实际运行恢复；不把“已经推送 Git”当作三者都完成。

- 技能：SKILL.md 与它引用的参考文件即可，不携带具体实例、运行 ID、IP、实际 PID、原始告警、秘密或生产回执。
- 安全源码：冻结所需 commit/树、manifest、必要构建产物或可复现输入，以及未夹带私有内容的工具源码。先检查包边界再交唯一写入方；只上传当前授权的仓库、路径和白名单。
- 实际运行恢复：在已授权私有位置保存必要基线/payload/分片的原字节、manifest、固定命令目录、提交 intent/start/exit、官方接收与最终回执、依赖来源与摘要、角色和配置绑定、验证结果及恢复前置条件。只保存哈希却丢失不可再生成的原字节，不是完整可恢复备份。
- 秘密：留在已有批准的秘密存储与加载方式中。源码和普通 Drive 交付不得携带凭据、env 值、原始 PM2 dump 或私有服务配置；实际运行证据仅进入当前已授权的私有 Library 或等价目的地，且仍排除秘密。

备份回执应列出精确路径、字节数、SHA256、目的地版本/对象以及仍需的外部依赖。上传后回读验证；仅有上传请求发出不能称备份完成。缺少依赖或证据时，具体标注哪些内容能恢复、哪些不能恢复，不伪造运行身份或旧 UNKNOWN 终态。

PM2 的 [startup/save 官方文档](https://pm2.keymetrics.io/docs/usage/startup/) 区分启动集成与保存进程清单。只在当前授权范围内核对两者；pm2 save 后需逐角色全字段回读及再次核对运行状态，不能额外配置启动服务，也不能将保存成功称为重启实演。


## GitHub/MCP 备份中断的分类与恢复

把工具显示、取消来源、执行生命周期、审批结果和远端状态分别记录。保留原始回执；发现旧解释错误时增加带时间的解释附录，不覆写历史原文。

- 仅有 `user cancelled MCP tool call`：记为 `CANCELLATION_SOURCE_UNKNOWN`。这是工具文字，不是用户点击取消的证据；不要要求用户承认取消。用户明确否认时，记录其澄清，不猜测平台根因。
- 用户明确停止或可核验的用户操作事件：记录该用户意图及作用范围，停止相关写入；普通工具字串不能替代此证据。
- 明确审核拒绝及理由：记为 `APPROVAL_DENIED`，保存精确动作、目标与缺少的授权。不能将它混为用户拒绝，也不能用后来拒绝倒推早先模糊取消的原因。
- 明确网络错误、deadline、会话终止：记录实际可见类别；未见此证据不得猜为超时。客户端中断不等于远端未执行。正常返回 isError 也不能确定后端根因。
- 一次恢复成功只证明该次操作恢复，不能声称平台误报根因已修。

### 提交前绑定与远端对账

提交前固定用户原授权来源、精确仓库/目标分支、拟上传文件清单与字节摘要、敏感性说明及排除项。重新核对仓库归属、私有性和实际可用权限；private 或 push=true 不是上传任意私有数据的授权。传递必要的原用户授权证据，不能用代理概括替代缺失许可。授权诊断不自动授权重新上传。在任何分段上传前，以完整最终manifest、文件总数、总字节量和内容类别绑定批准，同时固定本段与累计最终清单；只批准暂停的几件文件，不等于批准其余分段、最终累计tree或发布commit/ref。不要等末段才发现范围缺口。

对每次写保存操作名、参数摘要、开始/结束、原始响应和已暴露的 request/approval ID；没有的字段记未知。记录 functions.exec 的 running/completed 及合法续等，不把 yield 当作失败。不要终止仍在执行的 cell 后另起重复写。

结果不明时由原唯一 writer 只读对账：查预期 tree/blob、commit 及目标 ref，比较完整路径、mode、对象和内容摘要。`create_tree` 不等于 commit/ref 已发布。一次 GET 的 404/422 只表示检查时该对象不可取得，不能证明从未创建，更不能把读错误当作原写入原因。明确“Invalid object requested”与通用 422 分开；权限或网络读失败保持未决。

### 单 writer 恢复门

1. 确认原执行方已结束或交接，所有在途写已查明；其余协作者只读，不重复提交。
2. 若远端对象/目标ref已经精确符合预期，复用并补验，不重写。若出现不同对象或ref推进，停止并处理冲突，不强推。
3. 若仍未决，继续只读核验或报告缺口；经过一段时间、未出现在列表、或用户说“修好”都不能代替远端证据和授权。
4. 若明确被审核拒绝，先核对当前授权是否覆盖该动作、payload和目的地。缺失时只问这一项；充分证据到位后按当前工具规则原调用一次恢复。再次拒绝就停并报告，不切换工具、拆分payload或改通道绕过。
5. 对仅有模糊取消且远端未确认完成的调用，也先核对授权与在途状态，再决定是否获准原参数恢复；分类为 UNKNOWN 本身绝不发放重试权限。不得盲重试commit/ref；恢复后必须读取实际后置条件。

依据：[GitHub Git trees API](https://docs.github.com/en/rest/git/trees)区分创建tree与提交/更新ref；[MCP cancellation规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/cancellation)允许任一端发取消通知且说明完成竞态。规范用于制定核验措施，不用于替具体回执推定取消来源。
